## 背景：工作流已改成两层

原流程每条任务跑 `S1→S2→S3→S4→S5→S6`，其中 **S3 每次去搜网找参照** —— 已废除。

**第一层 · 建骨架（每桶一次）**：照真实站点复刻出一个可运行的空壳，产出 `skeletons/<bucket>/`。
**第二层 · 适配任务（每任务一次）**：
- `S1` 改契约：不再自由设计 FSM，改成**往骨架的字段槽上做映射**（数据填哪些槽、加什么筛选、藏第几层）
- `S2` 校验对象改成"映射是否覆盖所有 gui 放置 + 骨架槽够不够"
- `S3` **删除**
- `S4` 改成 **fork 骨架 → 按映射改字段/加页面/灌数据 → 写 ground_truth.spec.ts**
- `S5`/`S6` 不变

**核心原则（用户明确要求，已存 memory `skeleton-fidelity-over-coverage`）**：
骨架真实性优先于覆盖率。塞不进真实界面的任务数据就**不进 GUI**，留在磁盘当文件。不要为迁就任务改骨架。

## 已定的三件事

1. **不做登录墙** —— 薪资与完整职位描述直接可见（真站未登录时会打码成 `**-**元` 并截断描述，我们不复刻这个限制）
2. **纯静态前端** —— HTML/CSS/JS + 一份 JSON 数据，无后端。筛选/翻页/展开全前端实现（这正是要 agent 操作的东西）
3. **骨架自带 30 条占位岗位**，仅用于证明交互跑通；真实数据在第二层按任务灌

### 页面结构

**顶部导航**：深青渐变条 · BOSS直聘 logo | 首页 职位 公司 校园·海归 APP 有了 海外 无障碍专区 |（右）我要招聘 我要找工作 登录/注册

**搜索行**：`推荐 | ＋添加求职期望` | 搜索框 | 地图 | 搜索按钮（青色实心胶囊）

**筛选行 —— 10 个下拉，agent 的主要操作面**：
`城市 · 工作区域 · 职位类型 · 求职类型 · 薪资待遇 · 工作经验 · 学历要求 · 公司行业 · 公司规模 · 融资阶段` ＋ 右侧`清空`
- 单选下拉；选中项变青色并翻转箭头
- 薪资待遇选项实测：`不限 / 3K以下 / 3-5K / 5-10K / 10-20K / 20-50K / 50K以上`

**主体：两栏**。左侧岗位卡列表（窄，约 375px）+ 右侧详情面板（宽）。**点左卡右侧换内容，不跳页。**

**列表卡字段**：岗位名 / 经验标签 + 学历标签 / 公司 logo + 公司名 / 城市·区·街道

**详情面板区块**（自上而下）：
1. sticky 头部：岗位名 + 薪资 + 城市/经验/学历三个带图标标签 + 收藏 + 立即沟通
2. 职位描述（长文本，内部是"工作周期/每周工期/工作时间/结算方式/招聘截止时间/办公地点"这类结构化行）
3. 招聘者卡：头像 + 姓名 + 认证标 + 活跃状态 + `公司 · 职位`
4. 工作地址 + 内嵌地图
5. `查看更多信息` 按钮（展开公司信息）

## 开跑第一步：把参照抓全（截图远远不够）

用 claude-in-chrome，**一次 browser_batch 抓完**，不要只截图：
1. `read_page` 无障碍树 —— 真实层级与标签
2. `javascript_tool` 取**计算后 CSS** —— 精确色值/字体栈/圆角/阴影/间距刻度（比肉眼取色准）
3. `read_network_requests` 抓**岗位列表与详情的 API 响应** —— 真实字段名（jobName/salaryDesc/jobExperience/jobDegree/brandName/brandScaleName/brandStageName/areaDistrict/businessDistrict…）。**照真实字段名建槽位，比照截图猜字段像得多**，也正是第二层灌数据要对齐的东西
4. 补抓状态：翻页、空结果、独立岗位详情页、公司页
